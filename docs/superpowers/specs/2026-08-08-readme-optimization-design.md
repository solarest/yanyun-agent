# README 优化设计

## 目标

将根目录 README 从以架构目录为主的说明，调整为面向开源开发者的项目首页：读者应能迅速判断项目价值，并在一次连续操作中完成配置和启动。架构研究者与贡献者仍可通过清晰入口进入详细文档。

## 读者与成功标准

首要读者是首次访问仓库、希望运行并评估 WordLight Agent 的开发者；次要读者是贡献者与架构研究者。

完成后，README 应满足：

- 首屏说明项目用途、目标用户和当前技术定位。
- 快速开始使用真实仓库地址和实际脚本调用顺序。
- 快速开始覆盖环境变量复制、依赖安装、服务启动和成功验证。
- 已实现能力与规划能力不混写。
- 深度架构内容通过 `design/` 和 `docs/` 链接承载，而非占据首次阅读路径。
- 项目名称统一使用 `WordLight Agent`；仓库名作为克隆路径保留。

## 信息架构

README 按以下顺序组织：

1. 项目标题、一句话定位、仓库/技术状态徽章。
2. 核心价值和当前可用能力。
3. 快速开始：克隆、配置、安装、启动、验证。
4. 首次使用路径：配置模型、创建 Agent、开始会话。
5. 精简系统架构和扩展阅读链接。
6. 文档导航、开发命令、贡献、状态与许可证。

每个部分只保留帮助该读者完成下一步的信息。设计细节、接口契约和研究资料继续由现有 `design/` 与 `docs/` 文档承担。

## 命令与运行约束

快速开始必须匹配当前仓库脚本：`setup.sh` 在根目录执行依赖安装，且当前未设置可执行位；`bootstrap.sh` 在根目录启动服务，并要求后端 `.venv` 与前端依赖已存在。因此命令顺序固定为：

```bash
git clone https://github.com/solarest/yanyun-agent.git
cd yanyun-agent
cp backend/.env.example backend/.env
# 编辑 backend/.env，填写至少一个 LLM API Key
bash setup.sh
./bootstrap.sh start
```

启动成功后的验证地址为前端 `http://localhost:3000` 和后端文档 `http://localhost:8000/docs`。

## 范围与非目标

本次只改 README 及其必要的仓库元数据提示，不新增截图、GIF、许可证文件或贡献流程文件；README 会把这些列为后续建议，避免伪造不存在的资产或治理机制。

不改动服务脚本、应用代码、包名和现有设计文档。项目名称在 README 内统一，但代码中的既有命名不随本次改动迁移。
